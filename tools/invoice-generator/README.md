# invoice-generator — sdílený generátor fiktivních dokladů

Balík `invoicegen` (jen standardní knihovna Pythonu 3.12+) sdílený třemi
vstupními body:

- `demo/invoices/build.py` — demo faktury pro video (`tasks/demo-invoices.md`),
- `tests/corpus/cz/build.py` — korpus testovacích dokladů s očekávaným
  výsledkem (`tasks/testing-phase1.md`, `docs/test-corpus.md`),
- `demo/datasets/build.py` — demo datové sady z příběhu firmy
  (`tasks/demo-dataset-phase1.md`, `demo/datasets/README.md`).

| Modul | Obsah |
|---|---|
| `invoicegen/jsonc.py` | `load_jsonc` — komentáře `//`, trailing čárky, čísla jako `Decimal` |
| `invoicegen/checks.py` | kontrolní součty IČO, mod 11 čísel účtů, IBAN; validace identit vč. telefonů z nepřidělitelného rozsahu (`000` za kódem země, výjimka +1 555-01xx; `phone_parts` = jediná tabulka délek kódů zemí, sdílená s `render.fmt_phone`) a spisové značky korpusu bez popisku (`plain_court_registration`, #103 D103 — demo příběh vypíná, jeho šablony tisknou hodnotu doslova) |
| `invoicegen/compute.py` | výpočet řádků, rekapitulace DPH a součtů v `Decimal` (ROUND_HALF_UP) |
| `invoicegen/render.py` | formátování pro tisk, HTML ze šablony `{{key}}`, PDF přes Gotenberg; `render_rows` s volitelným sloupcem kódu položky (`code_column`) a detaily řádku (popis, EAN) pod názvem, jen když je řádek nese (#103 D102; výchozí volání = demo, bajtově shodné) |
| `invoicegen/expected.py` | očekávaný výsledek = papírová projekce canonicalu (`tests/corpus/projection.jsonc`), odvozená pole podle promptu, hodnoty netištěné samostatně z bloku `unprinted` datového souboru (platební reference = číslo dokladu, #103 D110), zapisovač JSON bez float |
| `invoicegen/fidelity.py` | věrnost tisku korpusu (#103 D105): identifikátory z očekávaného výsledku (`IDENTIFIER_PATHS` — číslo dokladu, IČO, DIČ, účet, IBAN, BIC, symboly, kontakty, spisová značka, kódy, EAN a popisy řádků) musí být v textu PDF z `pdftotext` (porovnání bez bílých znaků); `missing_identifiers` → `Finding(path, value)`, `summarize` po poli, `pdf_text` (`FidelityError` bez poppler-utils) — build korpusu `--fidelity=warn|error` |
| `invoicegen/registries.py` | ověření identit v ARES a VIES (síť, jen `build.py --verify-identities`), přepis `verifiedAt` |
| `invoicegen/corpus.py` | datový soubor korpusu: validace (vč. bloku `unprinted` — `paymentReference: docNumber` bez VS, `period: rows` jen s oběma daty v textu některého řádku v tištěném tvaru, `printed_date_forms` / `row_carries_dates`, #103 D110 / D112), přepisy per profil (`overrides`, alias), vynechané buňky, matice doklad × profil, jazyk šablon (`TEMPLATE_LOCALE`) |
| `invoicegen/datasetio.py` | zápis sady jako PHP: `dumps_dataset` (JSON jako `DatasetWriter`), `slug` jako `Slug::make`, `file_name`, `prune`, `php_json_numbers` (bloby analýz), `manifest` (pořadí klíčů `DatasetManifest`), `attachment_entry`, `sync_tree` (zápis jen změněných bajtů, úklid spravovaných sekcí) |
| `invoicegen/snapshot.py` | snímek ideální analýzy a obálka zprávy ve tvaru `MailExporter` bez vazby na korpus: `dataset_canonical`, `analysis_json`, `classification_json` (zpráva bez dokladu s pozorností), `analysis_record`, `message_record` |
| `invoicegen/rates.py` | kurzovní lístky korpusu (`tasks/testing-rates-isdoc.md` D72, D73): účetní datum dokladu (DUZP, bez něj vystavení), zrcadlo `ExchangeRateResolver` (poslední lístek ≤ D, nejvýš 7 dní, měna v něm, kurz za jednotku na 6 míst), výběr použitých a rezervních lístků, stažení ze služby kurzů jen pro `build.py --fetch-rates` (síť) |
| `invoicegen/dataset.py` | datové sady z korpusu (`tasks/testing-phase2.md`): základ profilu, sekce `exchangeRates/` ve tvaru exporteru (`tasks/testing-rates-isdoc.md` D72), vlastní firma, zpráva s ideální analýzou per buňka (adaptér nad `snapshot.py`; u podoby `pdfIsdoc` s ISDOC jako druhou přílohou, D75), deterministické sestavení `tests/datasets/cz/<profil>/` vč. `expected/` pro `dataset-verify`; přesunutá jména re-exportuje |
| `invoicegen/demoprint.py` | hodnoty pro demo šablony faktur (`invoice_values`, dřív v `demo/invoices/build.py`), převod kanonické identity na plochý tvar dema (`flat_party`), hodnoty pro šablony dokumentů spisovny (`registry_values`) |
| `invoicegen/catalogs.py` | číselníky Shipardu z repozitáře pro validaci příběhu: osnova, nabídka účetních položek, jednotky a zkratky, druhy položek, taxonomie štítků, druhy dokumentů spisovny, účely odeslání, šablony, pravidla daňových odpisů CZ (`AssetRules` z `world.assets`: skupiny, metody, sazby rovnoměrné metody, zaokrouhlení — #131 fáze 2c) |
| `invoicegen/timeline.py` | kotva a relativní data (`period_for`, `month_date`, `in_period`, `quarter_offsets`, fiskální rok), deterministická rozmanitost bez RNG (`spread`, `spread_decimal`), razítka a popisky období |
| `invoicegen/collation.py` | řazení jako MariaDB `utf8mb4_czech_ci` (`czech_key`: č, ch, ř, š, ž jako samostatná písmena, diakritika a velikost písmen až na dalších úrovních) a `robust_order` — jména, o jejichž pořadí rozhoduje jen diakritika nebo interpunkce |
| `invoicegen/story.py` | příběh firmy demo sady: `load_story` (soubory `story`, `partners`, `items`, `registry`, `mail`, `setup/`), validace (identity přes `checks.py`, odkazy, období, vyvážené mzdy, řazení jmen, překryv s identitami dema a korpusu, účet per měnu `own.bankAccounts` pro odběratele i dodavatele, blok `bank` — zůstatky, poplatky, platby mezd s protiúčtem nikomu nepatřícím, pravidla převodů `transfers` z účtu v cizí měně na CZK; dodavatel `language` / `currency` / `vatTreatment` se `supplyKind: services` a sazbou samovyměření u reverseCharge, locale šablony = jazyk — #131 D26, D28; blok `assets` — skupina typů a typ ze `setup/` s úplnou účetní skupinou, nastavení měsíčních odpisů a pole Majetek, karty s rovnoměrnou metodou v odpisové skupině ze `world.assets`, nákup jako samostatná faktura tuzemského dodavatele v měsíci mimo jeho pravidlo, zařazení do kotvy — fáze 2c, D41), `identities_for_checks` pro ARES / VIES |
| `invoicegen/model.py` | mezimodel rozvinutého příběhu (`DocRec`, `RowRec` vč. dimenzí `work_order` / `asset`, `MailRec`, `RegistryRec`, `PersonRec`, `WorkOrderRec`, `AssetRec` s plánem odpisů v okně, `Records`) |
| `invoicegen/expand.py` | rozvinutí příběhu: zakázky (`expand_work_orders` — paušály jako periodické zakázky s předpisem a evidencí období, `expand_projects` + `project_purchases` — projekty s dimenzí na fakturách a řádcích nákupu, #131 fáze 2b), majetek (`expand_assets` — karta se zařazením a plánem odpisů v okně, `asset_purchases` — samostatná faktura dodavatele s řádkem `purchase.asset` s účtem pořízení a kartou na řádku, `asset_cost_links` — faktury dodavatele od první po zařazení s kartou na řádcích; fáze 2c, D41), vydané doklady z pravidel (paušály z předpisu zakázky jako `InvoiceBuilder`: text dokladu s {období}, období, zdroj a dimenze; (cena z katalogu na dokladu v cizí měně = CZK ÷ kurz měsíce, `foreign_unit_price`, #131 D27; kurz chybí = `ExpandError`), přijaté faktury se zprávami a PDF (dodavatel se samovyměřením: doklad cz-217 / 21 %, papír 0 % + `supplyKind`, měna a kurz dodavatele, anglický předmět, tělo a šablona přes `corpusprint` — D28), prodejky a výdajové pokladní doklady, mzdy, zprávy k řešení, spisovna; číslování podle `docTypes.jsonc` (`format_number`, `assign_numbers`), model plateb (`payment_events`, D8/D18: odběratelé i dodavatelé, doplatek částečné úhrady, záměrně chybný VS `typo_reference`) |
| `invoicegen/assets.py` | majetek demo sady (#131 fáze 2c, D41): port měsíčního plánu účetních odpisů „účetně jako daňově“ nad rovnoměrnou metodou (`acc_monthly_plan` jako `AsTaxAnnualMethod`: roční částka rovnoměrné metody od měsíce po zařazení do prosince, podíl ze zbytku nahoru na koruny, poslední měsíc dorovná; `straight_annual` jako `CzTaxDepreciationRules::annualAmount`, `ceil_whole` jako `Amounts::ceil`) — jen pro souhrn ekonomiky, sada odpisy nenese (D38) |
| `invoicegen/workorders.py` | periodické zakázky demo sady (#131 fáze 2b, D32–D34): porty PHP periodické fakturace — `period_label` (`PeriodLabel`: názvy měsíců cs / sk / de / en jako ICU `LLLL yyyy`, čtvrtletí z cfgItem `periodTexts`), `doc_text` (`DocTextTemplate`), `period_bounds` / `due_periods` (`PeriodCalendar`, fakturace na počátku období), `rows_valid_at` (`InvoiceBuilder::rowsValidAt`), `invoice_from` / `date_start_for` (fakturovat od a zahájení relativně ke kotvě) |
| `invoicegen/bank.py` | bankovní výpisy demo sady (fáze 2a, #131 D17, D18, D22, U1): `build_statements` (události úhrad → transakce → měsíční výpisy per účet, zůstatek navazuje, poslední končí kotvou, poplatky), `expand_bank_docs` (otevírací doklad 221 / 701 s `fiscalPeriodType: opening`, vyrovnávací doklady mezd MD závazek / DAL clearing), **převody mezi vlastními účty** (#131 D26, `story.bank.transfers`: měsíčně k danému dni zůstatek účtu v cizí měně nad rezervou dolů na krok, `transfer.out` s kurzem měsíce + `transfer.in` v CZK = částka × kurz téhož dne, `transfer_amount_dom` = PHP `round(amount × rate, 2)`), validace (zůstatek ≥ 0, protiúčet nespárované platby, pár platba ↔ vyrovnávací doklad, kurz jen na účtu v cizí měně, obě strany převodu téhož dne a CZK = EUR × kurz) |
| `invoicegen/corpusprint.py` | hodnoty pro šablony korpusu (`tests/corpus/cz/templates/*.html`): lokalizované popisky `LABELS`, `COUNTRY_NAMES`, adresy se zemí, platební a datové řádky, klauzule reverse charge / osvobození, měna u částek, sloupec Kód / Code jen u dokladu s kódy, spisová značka s popiskem podle jazyka (#103 D102, D103) a řádek období jen tehdy, když ho hlavička tiskne (`unprinted.period = rows` ho vynechá, #103 D112) — `template_values(data, supplier, profile, computed, locale=, receipt=)`; dřív `build_values` ve skriptu korpusu, sdílené s demo sadou pro anglické faktury dodavatele z EU (#131 D28, kopie šablony `demo/invoices/templates/en.html`) |
| `invoicegen/economy.py` | souhrn ekonomiky příběhu (#131 D25): `summarize` ze stejných záznamů jako soubory sady — výnosy a náklady (mzdy, dodavatelé, pokladna, poplatky) v domácí měně kurzem dokladu, výsledek a zisk v %, měsíce ve ztrátě, podíl zahraničních odběratelů, nákup × prodej zboží, nejnižší a konečný zůstatek účtů, výnosy / náklady / marže projektů z dimenze zakázky (fáze 2b), karty majetku s plánem účetních odpisů v okně a výsledek po jejich zaúčtování (řádek pořízení `purchase.asset` náklad není — fáze 2c, D41); `format_summary` pro výpis `build.py`; cíle hlídá `tests/test_economy.py` |
| `invoicegen/errors.py` | `ExpandError` sdílená `expand.py` a `bank.py` |
| `invoicegen/doccalc.py` | výpočet dokladu jako `DocDocument::computeAmounts`: řádkové `computed`, rekapitulace metodou z hlavičky, dorovnání řádků na rekapitulaci, součty, zaokrouhlení na koruny, obrat MD u účetního dokladu; samovyměření (`SELF_ASSESSED_CODES`, cz-217 → pár cz-207): daň na řádku i v rekapitulaci informativně, celkem = základ, párový řádek `is_reverse_pair` mimo součty hlavičky |
| `invoicegen/dumpshape.py` | záznamy ve tvaru `dataset-dump` — jediné místo s konstantami z PHP exportérů (pořadí klíčů, float vs. int, prune, řazení souborů a slugy per sekce; obálka karty majetku `asset_record` jako `AssetExporter`, dimenze řádku v pořadí zakázka → majetek) |
| `invoicegen/pdfcache.py` | PDF přes Gotenberg jen při změně HTML (hash v `build-state.json` mimo sadu), jinak bajty z cílové složky |
| `invoicegen/demo.py` | sestavení demo sady: `build_demo_dataset` (příběh → záznamy → soubory → `sync_tree`), manifest s `country`, `provision` a `counts` všech sekcí |
| `invoicegen/reporting.py` | očekávání pro ověření zaúčtování (`tasks/testing-phase3.md`): mapování variant na řádky přiznání DPH a oddíly KH (`tests/corpus/cz/vat-reporting.jsonc`), záznamy `expected/vat.json`, `expected/costs.json` (v Kč kurzem k účetnímu datu) a `expected/exchange-rates.json` v `Decimal` nezávisle na Shipardu |

Vstupní body si přidávají `tools/invoice-generator` na `sys.path` a balík
importují; žádná instalace. Gotenberg: env `GOTENBERG_URL`
(default `http://10.199.6.210:3000`, `docs/render.md`).

## Testy

```bash
cd tools/invoice-generator && python3 -m unittest
```

`tests/test_demo_regression.py` hlídá, že demo kolekce dává stále stejné
HTML (sha256) a součty — demo se nemění, generátor se jen rozšiřuje.
Testy demo sady (`test_story`, `test_expand`, `test_demo`, …) používají
jako fixture skutečný příběh `demo/datasets/stories/it-servis/` a PDF
renderují falešným rendererem; sestavení s Gotenbergem dělá jen
`demo/datasets/build.py`.
